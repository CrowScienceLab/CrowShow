## 확인된 원인 및 수정

### 업데이트 다운로드

GitHub에는 v1.0.0과 v1.0.5(표시 1.0f)가 게시되어 있었습니다.
1.0f 설치 파일은 로컬 최종본과 같은 SHA-256이었지만, 체크섬 파일은
`SHA256SUMS-v1.0f.txt`로만 올라가 있었습니다. 이전 앱의 Rust 업데이트 검사는
`SHA256SUMS.txt`만 찾으므로 해당 릴리스가 검증 불가능한 상태로 처리됐습니다.

- 기존 릴리스와 파일을 다운로드·보관한 뒤 v1.0.5에 같은 내용의 `SHA256SUMS.txt`를 추가했습니다.
- 기존 설치 프로그램과 버전명 체크섬 별칭은 그대로 보존했고 1.0f 기능 설명을 갱신했습니다.
- 새 앱은 표준 체크섬을 우선하며 버전명 체크섬도 지원합니다.
- Windows x64 설치 파일 선택, 버전·파일명·동일 릴리스 URL 확인, SHA-256 형식 검사를 보완했습니다.
- 자동 확인을 통해 업데이트에 동의한 뒤 발생한 다운로드·설치 오류도 안내합니다.
- 서버 버전이 설치 버전보다 낮아도 최신 상태 안내에는 현재 설치 버전을 표시합니다.

### 대용량 PDF

초기 로더가 모든 페이지 크기를 순차 조회했고 썸네일 컴포넌트가 모든 페이지를 동시에 렌더링했습니다.
주 화면→로더→워커·저장 단계에서 원본 전체 버퍼의 추가 복사도 발생했습니다.

- 첫 페이지 크기만 초기 조회하고 현재 페이지의 크기는 이동 시 계산합니다.
- 큰 PDF는 `PDFDataRangeTransport`를 통해 요청 구간을 256KB 단위로 워커에 전달합니다.
- 워커의 자동 전체 선읽기를 끕니다. 원본의 SHA-256 계산과 첫 페이지 조회는 병렬 처리합니다.
- `IntersectionObserver`로 화면 주변 썸네일만 렌더링합니다. 미리보기 공간을 확보합니다.
- 주변 페이지를 순차 사전 렌더링하고 문서 교체 시 오래된 배경 작업의 캐시 재삽입을 막습니다.
- 불필요한 전체 버퍼 복사를 줄였습니다. 원본·SHA-256 문서 ID·저장 포맷은 보존합니다.

### 한글 표시

검증 문서: 경기그랜드투어-가이드북-국문.pdf, 131,761,690 bytes, 103페이지.
내장 한글 글꼴과 Identity-H 인코딩을 사용하며 PDF.js에서 CMap이 필요합니다.
기존 설정은 `Ensure that the cMapUrl API parameter is provided` 오류와 함께 한글을 누락했습니다.

- PDF.js CMap·표준 글꼴·WASM 이미지 디코더·ICC 색상 리소스를 빌드 시 로컬 포함합니다.
- `cMapUrl`, `cMapPacked`, `standardFontDataUrl`, `wasmUrl`, `iccUrl`을 설정했습니다.
- 인터넷 글꼴이나 CDN에 의존하지 않습니다. 각 리소스의 라이선스도 포함합니다.
